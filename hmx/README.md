## 対応表

- `audit/source.json`: 原典の SHA-256、対象ページ、ブランチ、確定状態。
- `audit/items.json`: 定義・定理・補題・系・注意・予想の原典上の位置。本文と付録の再掲を別の出現として保存する。
- `audit/figures.json`: 規則の図と、定理間の関係を示す図。
- `audit/conventions.json`: 番号のない定義、節全体の仮定、表記規約。
- `audit/ambiguities.json`: 原文の曖昧さと実装の未完了事項。両者を区別して読む。

`draft` は転記した草案、`partial` は一部だけの転記、`not_transcribed` は未実装である。`verified` への変更には、原典と Lean の両方向の照合が必要である。

## 確定までの順序

1. 原典の曖昧な箇所について、印刷された式と採用する修正を対にして確定する。
2. 未実装の構文・条件・ステートメントを埋め、すべての宣言の出典を確認する。
3. 量化順序、代入の有限性・冪等性、無条件の比較、個別の solved 条件、節全体の仮定を再照合する。
4. 全体ビルド、対応表検査、原典画像との再照合、PDF の同期を完了する。
5. 仕様確定を記録してコミットする。その後に証明計画へ進む。
